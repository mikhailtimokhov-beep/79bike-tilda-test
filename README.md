# 79BIKE — тестовая главная для Tilda

Перенос главной страницы прототипа 79bike.ru (сделан в Claude) в **отдельный тестовый проект Tilda** с автоматической синхронизацией.
Действующий сайт falcon-bike.ru, его домен, DNS, страницы, SEO и интеграции этим репозиторием не затрагиваются.

## Как это работает

```
Claude правит src/  →  git push в main  →  GitHub Actions: сборка → проверки
        → (только если всё зелёное) публикация на GitHub Pages
        → блок T123 в тестовом проекте Tilda при каждом открытии берёт последнюю версию
```

Страницу в Tilda после первой настройки **переиздавать не нужно**: в блоке T123 лежит только небольшой загрузчик (`tilda/t123.html`),
а сама главная обновляется на GitHub Pages.

| Папка | Что внутри |
|---|---|
| `src/` | Исходник прототипа (точная копия артефакта Claude). Главная — `src/rep/index.html`. Правки делаются здесь. |
| `scripts/build.mjs` | Сборка в `dist/`: запрет индексации, единый сброс кэша (`?v=`), совместимость с iframe, `version.json`. |
| `scripts/check.mjs` | Проверки: 375/390/768/1440/1920 px, ошибки JS, ресурсы, картинки, горизонтальная прокрутка, H1/title/description, якоря и ссылки, меню, встраивание в имитацию страницы Tilda. |
| `scripts/visual-diff.py` | Попиксельное сравнение исходника и сборки (запускается вручную). |
| `tilda/t123.html` | Код для блока T123 (адрес сборки подставляется при сборке; готовый вариант — `dist/tilda-t123.html` и на Pages: `/tilda-t123.html`). |
| `.github/workflows/deploy.yml` | Сборка → проверки → публикация → контроль, что опубликована новая версия. |

## Локально

```bash
npm install --no-save playwright@1.63.0 && npx playwright install chromium
npm test                    # сборка + все проверки, отчёт в check-report/report.md
python3 scripts/visual-diff.py
```

## Откат

- **Ошибка в новой правке** — ничего делать не нужно: проверки не пройдут, публикации не будет, на тестовом адресе останется прошлая версия.
- **Вернуть прошлую версию вручную:** GitHub → Actions → «Тестовая главная — сборка и публикация» → Run workflow → в поле `ref` указать коммит или тег → Run. Либо `git revert <коммит>` и push.
- **Полностью отключить от Tilda:** в тестовом проекте Tilda выключить или удалить блок T123 и опубликовать страницу. На действующий сайт это не влияет.
- **Удалить тестовую публикацию:** Settings → Pages → Unpublish.

## Ограничения (честно)

- Главная показывается во фрейме на весь экран. Дизайн, анимации и скрипты работают 1:1, но для поисковиков содержимое находится на адресе GitHub Pages, а не на Tilda. Для теста это нормально (тест закрыт от индексации). Для боевого запуска нужен другой вариант — см. отчёт о переносе.
- Tilda показывает код T123 только на опубликованной странице; в редакторе и предпросмотре виден текст кода — так работает Tilda.
- Формы в прототипе демонстрационные: заявки никуда не отправляются, реальных заказов не создаётся.
- Tilda API — только чтение (экспорт), поэтому записывать код в Tilda автоматически нельзя; синхронизация идёт через внешнюю сборку.
- GitHub Pages кэширует файлы до 10 минут; загрузчик всегда берёт свежий `version.json`, поэтому новая сборка видна сразу или почти сразу.
